# Security note (prototype)

**Protected:** argon2 password hashing; signed JWT (HS256, 2 h, role claim) with the role re-checked against the database; login rate limit (5 failures → 60 s per email + IP); role checks on every route and object-level checks (patients only see their own appointments, intakes, records; nurses only their hospital's queue and never diagnoses or prescriptions; doctors only patients they have an appointment with, filtered by `ehr/history_policy.py`); audit log of every history/prescription/FHIR view, visible to the patient; action log of every staff action; Pydantic validation with `extra="forbid"` on registration (no phone or ID fields can be stored); CORS limited to `FRONTEND_ORIGIN`; security headers (CSP, X-Frame-Options, nosniff, no-referrer, no-store); secrets only in `.env`; no model name or key in code; logs carry ids and decisions only (tested), emails are redacted and query strings stripped from access logs; the browser sends text only, audio never reaches our server; the service worker caches the app shell only, never API responses; Person A's unauthenticated kiosk routes are off unless `ENABLE_LEGACY_KIOSK=true`.

**Out of scope for this prototype:** encryption at rest, key rotation and HTTPS termination (deploy behind TLS), regulated consent flows and identity verification, real retention/deletion policy, multi-worker concurrency (capacity lock is per process), penetration testing, certified compliance (e.g. DPDP Act, ABDM, HIPAA-like regimes). Browser speech recognition in Chromium sends audio to the browser vendor's service; that is outside our code and should be disclosed to users.
